# Code review: Verify multi-decision builds

- **Reviewed:** `git diff 6d12806...HEAD` at `dc97560` (7 commits).
- **Spec:** [Phase 2 requirements](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/requirements.md), [input contract](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/inputs.md), and [merge criteria](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/validation.md).
- **Checks:** `git diff --check` and `npm run typecheck` passed. `npm test` passed all 38 validation tests and 5 offline browser tests. The findings below describe cases those checks do not cover.

## Standards

### Documented breaches

1. **High — Valid Case Input IDs can break verification and rendering.** [Verification](../src/verify-categorical.ts#L20-L29) and the [browser](../src/app/main.tsx#L119-L120) look up IDs on ordinary objects without checking ownership. For an allowed ID such as `constructor`, an omitted value resolves to an inherited function: verification rejects the missing case, and the categorical UI can throw when rendering. The [input contract](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/inputs.md#L38-L44) allows nonblank IDs, and [AGENTS.md](../AGENTS.md) requires missing Case Inputs to stay distinct. Use own-property lookups or a `Map` and cover both paths.
2. **High — Verification rounds exact numeric inputs before evaluation.** [Verification](../src/verify-categorical.ts#L9) parses JSON numbers as JavaScript `Number`s; `9.9999999999999999` becomes `10`. Verification and the browser therefore disagree at a threshold of `10`, contrary to the [input contract](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/inputs.md#L51-L54). Preserve the numeric literals through verification.
3. **Low — Duplicate-label diagnostics differ for unused inputs.** [The v2 validator](../src/read-model.ts#L285-L293) reports only the Case Input ID. The [XML rules](../dev-docs/specs/2026-11-21-prove-offline-path/xml-model.md#L21), retained by the [v2 contract](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/inputs.md#L18-L19), require both colliding value IDs. Reuse the [existing value validator](../src/read-model.ts#L158-L172).

### Code smells (judgment calls)

4. **Medium — Possible Duplicated Code.** [The v2 parser](../src/read-model.ts#L257-L293) constructs a synthetic v1 model (`attributes: { version: "1" }`), then separately validates unused inputs (`// Validate even unused Case Inputs through the same value and label rules.`). The diagnostic above shows the two paths already diverge. Share the validators and validate each declared input once.
5. **Low — Mysterious Name.** [`verifyCategorical`](../src/verify-categorical.ts#L8) also calls `compareDecimals` to enforce numeric boundary coverage. Rename the function and file to `verifyCases` / `verify-cases.ts`.

## Spec

1. **High — `--replace` can delete a directory that was never a build.** [The destination guard](../src/build.ts#L50-L54) rejects only the filesystem root. The [replacement path](../src/build.ts#L59-L85) can move and recursively delete an unrelated destination; targeting `.` can replace the repository itself. [Requirements § Publication](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/requirements.md#L40): “Replace an existing build only on explicit request and preserve it if validation, verification, generation, or publication fails.”
2. **High — Concurrent publication can displace the known-good build.** Between the [replacement renames](../src/build.ts#L65-L78), a [default publisher](../src/build.ts#L89-L103) can claim the vacated destination. Replacement and rollback then both fail, leaving the previous build at a hidden backup path instead of its original entry point. The [failed-rerun tests](../tests/build-output.validation.test.ts#L139-L155) cover pre-publication failures only. [Merge criteria](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/validation.md#L11): “Failed reruns, including failed explicit replacement, preserve the previous artifact byte for byte and do not publish an incomplete app.”
3. **High — Numeric cases round before reaching the exact evaluator.** [Case parsing](../src/verify-categorical.ts#L9) and [boundary classification](../src/verify-categorical.ts#L23-L39) turn `9.9999999999999999` into `10`. An in-memory check confirmed that it was scored as applicable and did not count as below, excluding a correctly modeled decision. [Input contract](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/inputs.md#L52-L53): “Compare finite case values without rounding across the threshold.”
4. **Medium — A valid ID breaks missing-input handling.** [Verification](../src/verify-categorical.ts#L20-L29) treats inherited properties as supplied values. An in-memory check with the ID `constructor` confirmed that omitting the input rejects the build. [Browser initialization](../src/app/main.tsx#L155) has the same lookup issue. [Input contract](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/inputs.md#L38): “IDs are stable, nonblank strings compared exactly after XML parsing.” [Missing inputs](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/inputs.md#L71): “Omit an input to represent missing evidence.”
5. **Medium — The guidance check bypasses the evaluator’s actual action.** [Verification](../src/verify-categorical.ts#L41-L46) substitutes the XML guidance ID for the action returned by `evaluateDecision`, so a wrong applicable action with the right score would pass. [Requirements § Verification gate](../dev-docs/specs/2026-11-22-verify-multi-decision-builds/requirements.md#L37): “Compare each modeled decision against independently authored expected outcomes for applicable, unmet, and missing cases, including expected guidance and score where applicable.”

**Summary:** Standards: 5 findings (3 documented breaches, 2 smells); most serious: rounding at numeric thresholds. Spec: 5 findings; most serious: `--replace` can delete unrelated output directories.
