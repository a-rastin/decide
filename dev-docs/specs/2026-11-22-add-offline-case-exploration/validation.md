# Phase 3 validation and merge criteria

[Requirements](requirements.md) · [Plan](plan.md)

Use synthetic Source Material and synthetic cases only. Expected results must be independently derived from the fixture's probability tables and source predicates, not generated by the evaluator under test.

## Fixture and build verification

- [ ] The v3 fixture includes a routed build with a multi-input decision, a shared Case Input across decisions, and an unrelated input. Include a categorical sweep with comparable and inapplicable values and a numeric sweep in a declared unit with samples below, at, and above a threshold. Make at least two inputs produce distinct nonzero score spans, with a joint edit producing a different result from either isolated edit. Include a latent node and a multi-parent dependency and at least one posterior that cannot be read directly from any action table row.
- [ ] Use the public build command to generate the fixture and inspect the reported output. It contains the original XML byte for byte, local assets, and separate coverage and test reports. Independent cases cover applicable, unmet, and missing results; scoreable cases check the selected action ID and score, and threshold cases exercise either side and exact equality. Include cases for optional evidence, an explicitly required score input, and zero-likelihood evidence.
- [ ] Focused evaluator checks distinguish a decisive conjunction or disjunction with an unanswered operand from a genuinely indeterminate condition. Applicable but unscoreable guidance retains its source-supported action and reason, without a score.
- [ ] Reject malformed tables (missing or duplicate parent rows, invalid probabilities, or non-normalized distributions), dangling references, cyclic graphs, ambiguous numeric partitions, inconsistent sampling declarations, and models outside any supported inference limits. A rejected build does not publish or change an existing artifact, including when replacement was requested.
- [ ] Force an independently authored expected-result mismatch. In a mixed build the failure names the case and decision, unaffected verified decisions still work, and the app is labeled partial. When none verify, no new app is published. A successful default rerun leaves the earlier build unchanged.
- [ ] Existing v1 and v2 build invocations and fixtures still pass. The six-week example retains the 1% Do-Not-Consider Score when applicable, not a clinical probability. The Phase 2 mixed fixture retains its threshold behavior, partial notice, excluded decision, and report semantics. Legacy decisions with no meaningful variation explain why and still offer the sandbox.

## Offline browser acceptance

Build through the public command, then open the printed `index.html` through `file://` with Playwright in offline mode and with service workers blocked. Repeat the exploration checks after relocating the entire output folder. Observe no network requests, sockets, or uncaught page errors; no server or agent host can be required.

| Exercise | Expected visible result |
| --- | --- |
| Open a routed build and choose a verified Clinical Decision | The research-only notice is visible, routing precedes case questions, and only relevant Case Inputs appear. Partial builds display the partial notice and never offer excluded guidance. |
| Establish a scoreable original case and inspect both sweeps | The result shows source reason and citation. Each range and sample score matches an independently computed outcome holding the other inputs fixed. The joint-edit result never appears in either one-input sweep for this baseline. Bars rank by comparable score span. |
| Inspect categorical and numeric samples | Every modeled category is listed. Numeric samples show declared values and units, including the exact threshold boundary. A tested value that fails applicability identifies the source condition, has no score, and contributes no range endpoint. |
| Try missing or invalid evidence and an input with no numeric sampling declaration | Missing and invalid are distinct from known unmet conditions. Unavailable scores do not become zeros or stale ranges. Skipped sweeps explain why they cannot run. Equal comparable scores are explicitly unchanged, not an empty bar presented as evidence of missing data. |
| Open the sandbox from an unscoreable baseline | It is available and can produce valid guidance for the variant despite the missing, invalid, or unmet original. Both sides remain labeled; the unavailable state explains why a numeric comparison cannot be made. |
| Edit several variant inputs and reset | Variant guidance and score match the joint case. Original controls, guidance, score, and chart stay unchanged. Reset copies the current original values back into the variant, restoring parity without writing to original inputs. Editing an original value while a draft is open updates the chart from the original but does not edit the draft. |
| Switch decisions and return | A shared original value carries over by ID; a different input with the same label does not inherit it. No prior sandbox override survives the switch. |
| Navigate with the keyboard and inspect the chart without hover | Inputs, reset, and comparison content are operable or readable without a mouse. Labels and the text or table equivalent identify the original and variant, tested values, scores, and unavailable states without relying on color. |

## Ready to merge when

Run from a clean checkout with Node.js 24 or later:

```sh
npm ci
npx playwright install chromium
npm run typecheck
npm test
```

Vitest covers model and build contracts plus focused inference checks. Playwright covers the generated app. Run the documented v3 fixture invocation and inspect both reports. Record the commands, results, and any manual accessibility checks in the implementation handoff. Do not mark Phase 3 complete until the checks above pass; they establish offline synthetic behavior, not clinical validity or first-release readiness.
