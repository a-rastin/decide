# Tech stack

| Layer | Decision |
| --- | --- |
| Build tooling | Node.js, npm, and TypeScript for normalization orchestration, model validation, artifact generation, and verification. Use external document conversion or OCR tools where needed; keep them out of the generated app. |
| Agent integration | One shared workflow for Codex, Claude, and OpenCode, with host-specific installation or invocation where needed. The agent-followable prompt and one-line installer install the same release. Check for missing requirements and install them project-locally by default; obtain explicit permission for system-wide changes. |
| Model | Documented, versioned Decide XML schema. Validate structure and model invariants before generation. XML is authoritative; derive any browser representation from validated XML at build time. Keep source applicability conditions distinct from clinical outcome probabilities and model only mutually exclusive actions in the same distribution. |
| Generated app | A shared React and TypeScript UI using HeroUI v3 (`@heroui/react` and `@heroui/styles`). Bundle the UI, styles, and inference runtime into local browser assets. Ship model data with the bundle or embed it in the page; do not rely on a CDN, runtime `fetch` of local files, or a server. The entry point must open directly via `file://`, with no internet, AI API, Node.js, or agent host required. |
| Case evaluation and exploration | Use the same applicability and scoring logic for the original case, the tornado chart for each modeled decision’s selected option, and the What-If Sandbox. Keep model assumptions fixed and sandbox edits separate from the original Case Inputs. A sensitivity run changes one relevant input at a time, tests all valid categories or uses source- or model-defined numeric ranges and thresholds, and shows tested values and units where applicable. Show original and what-if guidance side by side, with scores where comparable. Identify the source condition for inapplicable guidance. If no meaningful comparison exists, explain why instead of showing a zero or empty chart, and keep the sandbox available. |
| Verification | Automate XML and inference checks and test representative synthetic cases where guidance applies, does not apply, or cannot yet be evaluated. Open the generated `index.html` directly from disk with networking disabled and verify that each sensitivity bar varies only one input, inapplicable states are not scored in comparisons, and sandbox edits and reset leave the original case unchanged. Report failures by decision and keep coverage reporting separate from test reporting. |

The HeroUI packages are in `package.json` and `package-lock.json`. When implementing the UI, use React 19+ and Tailwind CSS v4 as required by [HeroUI v3](https://www.heroui.com/docs/react/getting-started/quick-start). In the app's main stylesheet, import `tailwindcss` before `@heroui/styles` and compile both into local CSS at build time.

Choose the bundler, test runner, XML validator, inference implementation, and document conversion tools when the corresponding phase needs them. Prefer the smallest choice that meets that phase's exit check without weakening the [user specification](../user-specification.md).
